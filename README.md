# Осколки судьбы · Shards of Fate

Браузерная pixel roguelite RPG на TypeScript, React и Phaser. Исследуйте процедурный мир в одиночку или с друзьями: передвижение по клеткам, сезонные участки 35×35, независимые переходы героев и встречи с врагами. Сетевая игра поддерживает до четырёх игроков; поход первого акта завершается победой над четырьмя сезонными боссами.

## Запуск

Нужен Node.js 22.12+ (проверяется на Node 24).

```sh
npm ci
npm run dev
```

Откройте адрес, выведенный Vite (обычно http://127.0.0.1:5173). Игра занимает всё окно браузера. Главное меню предлагает продолжить сессию, начать новую игру, открыть заглушку настроек или выйти. Выход пытается закрыть вкладку; если браузер запрещает, появляется экран выхода. «Новая игра» открывает общее лобби: выберите одного из девяти героев, сложность и seed. «Играть» начинает одиночный поход, а «Пригласить» создаёт сетевую комнату и ссылку для друзей. Нажатие на карту задаёт движение своему герою. Кнопка меню справа снизу ставит одиночную игру на паузу и позволяет сохранить сессию и вернуться в главное меню.

## Игра с друзьями

В одном терминале запустите сервер, в другом — клиент:

```sh
npm run dev:server
```

```sh
npm run dev
```

Хост выбирает «Новая игра», героя, seed и сложность, затем нажимает «Пригласить» под костром внутри сцены выбора персонажа. Создаётся сетевая комната и открывается окно со ссылкой вида `https://адрес-игры/#invite=ABC234` и кнопками «Скопировать» и «ОК». Каждый участник, включая хоста, выбирает героя и нажимает «Готов». Предварительный выбор не занимает персонажа: если несколько людей выбрали одного героя, его получает первый нажавший «Готов». После этого выбор блокируется до нажатия «Не готов», а у героя появляется отметка готовности. Когда готовы все участники, у хоста кнопка «Не готов» заменяется на «Играть». Новый участник или отмена готовности откладывает старт. В комнате до четырёх подключённых игроков, вход возможен только по ссылке.

К уже начатому походу можно присоединиться по той же ссылке. Лобби показывает исходный пул героев похода: выберите свободного и нажмите «Готов». Хост передаст текущее состояние, после чего откроется игра. При выходе гостя его герой остаётся в мире и освобождается для другого участника; добавлять новых героев в начатый поход нельзя.

В локальной сети хост открывает игру по доступному друзьям адресу компьютера, например `http://192.168.1.10:5173`, и уже с него создаёт приглашение. Ссылка сохраняет адрес открытого сайта: `localhost` и `127.0.0.1` автоматически не заменяются и на другом компьютере указывают на него самого. Vite проксирует `/rsocket` на сервер `127.0.0.1:8787`. Для другого сервера администратор может задать `VITE_RELAY_URL` перед сборкой клиента или `RELAY_TARGET` при запуске Vite; адрес сервера не вводится игроками и не передаётся в приглашении. Для игры через интернет сервер и сайт должны быть доступны друзьям; HTTPS-сайту нужен `wss://` адрес или проксирование `/rsocket` через тот же HTTPS-домен.

Сеть использует [CKATEPTb/rsocket-ts](https://github.com/CKATEPTb/rsocket-ts): `rsocket-browser` в браузере и `rsocket-server-ts` на Node.js. Клиент сразу выполняет своё действие и локально рассчитывает движение, переходы, поведение врагов и бои тем же ядром, что и хост. Протокол v11 передаёт идентификатор и игровой тик команды; хост подтверждает обработанные команды в последовательных кадрах событий. Клиент восстанавливает подтверждённое состояние и повторяет ещё не подтверждённые действия. Это позволяет двигаться и видеть развитие боя без ожидания сетевого ответа. Предсказание ограничено пятью секундами без свежего кадра хоста.

Все клиенты генерируют геометрию мира из общего seed. У каждого героя своя последовательность кубиков: результат определяется seed комнаты, постоянным ID и личным счётчиком, который сохраняется между боями. Например, `2d4` Вампира расходует два номера последовательности `hero:vampire`; действия других героев и отдельные бои её не сдвигают. У врага результат зависит от того же seed и его постоянного ID из генерации мира, но счётчик начинается с нуля в каждом новом бою и хранится только внутри этого боя. Отображаемое имя персонажа на броски не влияет. Патрули используют отдельный временный RNG группы и её решения, не расходуют боевые кубики и не передают изменения их счётчиков. Общий счётчик комнаты остаётся только диагностикой. По сети идут команды, компактные события движения и боёв и изменения счётчиков только участников сделанного боевого хода. Полные счётчики героев и текущих боёв передаются со снимком при входе в идущую игру и продолжении сохранения. Сервер связывает команды с героем готового участника. Базы данных, журнала похода и серверной симуляции нет.

Хост сохраняет личные счётчики героев; новая ссылка комнаты их не сбрасывает. При восстановлении уже идущего боя сохраняются и его счётчики врагов, поэтому переподключение не начинает их броски заново. Между разными боями счётчики врагов не переносятся; для убитых врагов вне активного боя достаточно их ID. При загрузке сохранений v5 записи врагов удаляются из общего банка, а счётчики в текущих боях сохраняются. Более старые сетевые сохранения с одним общим счётчиком продолжаются с нулевых личных счётчиков: восстановить прежнюю историю каждой сущности из общей суммы невозможно. Мир, раны и прогресс сохраняются. Для совместной игры все участники должны использовать текущий клиент с протоколом v11.

Меню участника не ставит общий мир на паузу. Герои могут находиться в разных участках и вести отдельные бои. Свободный живой герой присоединяется, если его pathfinder строит путь длиной **10 клеток или меньше** до любого героя или врага, уже участвующего в этом бою. Учитываются препятствия и настоящий маршрут; визуальный радиус света не определяет участие. Правило действует при начале боя и при подходе к уже идущему бою. Присоединившийся герой может привлечь следующего, но герои из другого активного боя не переходят между боями. Позднее подкрепление не сбрасывает раны, кубики и текущие ходы; новый герой получает инициативу со следующего раунда.

После гибели своего героя можно наблюдать за отрядом. Выход или отключение хоста закрывает комнату и отключает всех гостей; роль хоста не передаётся. Поход автоматически сохраняется только в браузере хоста в общий слот сохранения. «Продолжить» открывает новое лобби и создаёт новую комнату со свежей ссылкой, прежним seed, сложностью и полным исходным пулом героев. Гости могут заново занять свободных героев. Комнаты исчезают при остановке сервера.

Для запуска без наблюдения за исходниками используйте `npm run start:server`. Настройки и ограничения сервера описаны в [apps/server/README.md](apps/server/README.md).

Слева сверху находятся строки героев, справа — круглая мини-карта с обзором до трёх колец и общими координатами X/Y относительно стартового костра. Вход в участок раскрывает его выходы и непосредственных соседей; дальнейшие связи неизвестны до посещения соответствующего участка. Открытые сведения сохраняются. Значки видны только внутри круга, а известные проходы к внешним соседям обозначены линиями до его границы. Неисследованные соседи показаны простыми точками без раскрытия сезона и алтаря. Панели полупрозрачны, при наведении показывают подробности. Клики и касания сквозь них всегда передаются миру; сама мини-карта не выбирает маршрут.

Слева снизу находится кнопка «Экипировка». Нажатие открывает над ней компактную панель из трёх столбцов по пять ячеек: броня, оружие с аксессуарами и умения. Пояс и расовая способность исключены. Повторное нажатие или Escape закрывает панель; по умолчанию она скрыта. Клик или тап по ячейке закрепляет описание, на компьютере работают и подсказки при наведении. Кнопка, панель и описание принимают нажатия, остальная карта остаётся доступной; экипировка не ставит игру на паузу. На низких экранах прокручивается только содержимое панели.

Доступны Страж, Вампир, Паладин, Жрица, Друид, Некромант, Разбойник и Следопыт, Маг. Каждый имеет собственные направленные анимации, скорость, начальную экипировку, классовое и личное активное умение и пассивный эффект. Амулет и кольца пока пусты. Описания экипировки показывают вклад в ресурс частей тела и общую защиту, включая частично действующие предметы при утрате конечностей. Два дополнительных слота навыков остаются пустыми. Добыча, замена предметов и протезы пока не реализованы. Герой может выбирать себя целью поддержки: Страж защищает себя, лечение Паладина распространяется на него самого без рекурсивных цепочек. Действие всегда выбирает игрок. Вызов на 3 хода вынуждает врагов атаковать применившего его героя, включая массовые атаки.

Навыки используют явные кубики и перезарядки в собственных ходах. Маг выпускает четыре заряда с отдельной проверкой `1d20` и уроном `1d6`; Горение в конце хода наносит урон по числу зарядов и теряет один заряд. Ауры видны под персонажем и сопровождаются постоянными эффектами: жёлтым Благословением, зелёной регенерацией, костяным вихрем щита и другими. Полная таблица девяти героев, длительности и правила стаков — в [решении о навыках](docs/adr/0013-hero-dice-skills.md).

Для будущей находки и экипировки подготовлены [400 изучаемых навыков](docs/reference/SKILL_CATALOG.md)
в пятнадцати школах: прямые действия, ауры, поддержка отряда, случайные цели,
атаки по любому участнику и умения с разным действием на союзника и врага.
У каждого есть отдельная иконка, снаряд и редкость: обычная, редкая, эпическая
или легендарная. Пулы распределены в пропорции 4:3:2:1 — 160 обычных,
120 редких, 80 эпических и 40 легендарных умений. В каждой школе есть
варианты всех четырёх редкостей, включая минимум два легендарных.
Мастерская с фильтром редкостей —
`artifacts/skill-catalog-preview.html` при запущенном Vite; текущие навыки героев
сохранены. Выбор случайной цели использует видимый кубик из личной
последовательности исполнителя. [Механика каталога](docs/adr/0017-skill-catalogue-and-target-dice.md).

Каталог экипировки содержит **500 новых полных комплектов** в двадцати тематических
коллекциях: 200 обычных, 150 редких, 100 эпических и 50 легендарных. В каждом —
пять частей брони, амулет, два кольца и совместимый набор оружия/щита для рук.
Бонусы за 2, 4 и 6 разных активных предметов складываются; двуручное оружие
считается одним предметом. [Каталог комплектов](docs/reference/EQUIPMENT_CATALOG.md).
Комплекты дают бонусы атрибутов или поддерживаемые ауры с иконкой и визуальным
эффектом. Редкость каждой вещи видна в названии и тонкой рамке: обычная —
серебристая, редкая — голубая, эпическая — фиолетовая, легендарная — золотистая.

Мастерская `artifacts/equipment-catalog-preview.html` позволяет примерять наборы
и отдельные вещи, сравнивать атрибуты и подтверждать выбор. До подтверждения
изменения можно отменить. После подтверждения снятые вещи возвращаются в запас,
а не выбранные варианты остаются в локальном каталоге мастерской. В походе
нажатие на находку забирает её в скрытую сумку. Сравнение и экипировка доступны
через слоты персонажа; заменённые вещи и изученные навыки возвращаются в сумку.
Закрытие добычи удаляет только несобранные награды после предупреждения.
[Примерка добычи](artifacts/reward-fitting-preview.html).
[Правила экипировки и примерки](docs/adr/0023-equipment-collections-and-fitting.md).

У союзников шесть отдельных ресурсов: голова, тело, две руки и две ноги. Стартовая база даёт 25% ресурса, комплект — 75%; голова слабее остальных частей. Враги сохраняют обычное HP. Перед прямой атакой по герою независимый d20 без бонусов выбирает место: 1 — мгновенный промах, 2–11 — тело, 12–13 — левая рука, 14–15 — правая рука, 16–17 — левая нога, 18–19 — правая нога, 20 — голова. Затем идут обычные попадание и урон. Защита общая, предметы не ломаются. Яд и горение повреждают тело. Попадание в уже утраченную конечность направляется в тело; лишний урон уничтожившего конечность удара не переносится.

Боевые навыки лечения распределяют один общий объём между повреждёнными сохранившимися частями пропорционально их максимальному ресурсу; после заполнения части остаток перераспределяется. Жрица замечает критическую рану отдельной части, даже когда остальные здоровы. Потерянные конечности не отрастают. Нулевой ресурс головы или тела, а также потеря обеих рук и обеих ног выводит героя до следующего похода. С одной рукой доступны текущие атаки и умения; без обеих рук остаются движение и пассивные эффекты. Привязанные к утраченной руке оружие и кольцо недоступны, парная экипировка действует только на сохранившуюся половину.

Состояние частей видно в строках отряда и подробно в «Экипировке», в том числе на телефоне. Каждая целая нога даёт половину скорости; повреждение снижает эту долю пропорционально ресурсу. Без ног, но с рукой герой ползёт со скоростью 10% без бонусов обуви. Спрайты показывают повреждения, отсутствие конечностей, хромоту и ползание. Раны сохраняются между боями, участками и загрузками, а оценки победы используют текущее состояние отряда.

На границе бывает несколько проходов, обозначенных стрелками поверх окружения и затемнения. Показываются только выходы, до которых свой герой может дойти из текущей области; доступные выходы за экраном показаны отдельными указателями у его края. Клик или тап по стрелке прокладывает маршрут к соответствующему выходу; достигнув его, отряд переходит в соседний участок. Перетаскивание стрелки не задаёт маршрут; выбранный с клавиатуры указатель можно активировать Enter или пробелом. Некоторые области одного участка разделены: чтобы попасть в них, выйдите к соседу и вернитесь через другой вход. Автоматических обходов через другие участки нет.

Курсор отмечает клетку кругом с толстой рамкой. Препятствия и области, до которых сейчас нельзя дойти, отмечены кругом с крестиком того же цвета; маркер виден поверх окружения. Нажатие на недоступную клетку не выводит всплывающих сообщений. Конец выбранного маршрута также обозначен кругом.

Скорость передвижения — отдельный от боевой инициативы атрибут в подсказке героя. Базовые 100% означают 280 мс на клетку; у девяти героев небольшие различия, Разбойник быстрее (110%). Бонус скорости сохраняется вместе с героем и готов для будущих предметов. Анимация согласована с шагами; меню и бой останавливают движение.

На открытой земле растут низкие округлые кусты, сквозь которые можно пройти. Шаг в куст занимает вдвое больше времени с учётом скорости героя и его бонусов; на свободной земле возвращается обычный темп. Поиск пути героя учитывает эту задержку и предпочитает более быстрый обход, когда он есть. Мобы проходят кусты с обычной скоростью при патрулировании и преследовании; их маршруты не учитывают замедление от кустов. Кусты не занимают полы домов, входы, выходы и места важных объектов; старые маршруты и проходимость карты сохраняются. Заросли с высокими прямыми стеблями убраны.

Герои и враги анимированы спереди, сзади и сбоку; ступни, контактная тень и выделение имеют общую точку опоры. Камера всегда плавно сопровождает своего героя. Перетаскивание отменяет клик и не перемещает камеру или героя; кнопки возврата камеры и команды Home нет. Ручного зума нет; масштаб подстраивается под окно, камера всегда остаётся внутри участка. Небольшие валуны лежат отдельно с зазорами, крупные каменные участки образуют цельные скалы 2×2, 2×3, 3×2 и 3×3. По свободной земле за высоким объектом можно кликнуть. Прозрачность включается только при перекрытии героя, курсора или пути над проходимой землёй; низкие валуны остаются непрозрачными. Системная настройка уменьшения движения отключает вторичные анимации и задержку камеры.

Каждый сезон занимает 10–15 колец; радиус мира — 40–60 участков. Детальные участки создаются по мере исследования. Мини-карта всегда показывает окрестности текущего участка. Среди лесов встречаются дома, развалины, колодцы и небольшие поселения с проходами и дворами. В новых мирах поселение выбирает один дом (60%), два (35%) или, изредка, три (5%); размещение учитывает свободное место, точки интереса и проходы. Выбор зависит от seed, включая стартовый участок. Уже созданные и сохранённые миры сохраняют прежнюю планировку. Сейчас это окружение без добычи и событий.

Из дымоходов домов поднимается лёгкий дым: он расширяется и рассеивается над крышей, помогая замечать жильё в темноте. Дым не перехватывает клики, сохраняется при раскрытии крыши и замирает при системной настройке уменьшения движения.

Костры горят анимированным пиксельным пламенем: языки огня меняют высоту и изгиб, а над поленьями поднимается небольшой рассеивающийся дымок. Тёплый свет мягко мерцает. При системной настройке уменьшения движения огонь и дым замирают, освещение остаётся постоянным.

Клетка костра непроходима: маршруты обходят огонь. Клик по костру ведёт на соседнюю доступную клетку и открывает отдых. Бесплатный отдых полностью лечит сохранившиеся части живого отряда на участке; во время боя и преследования он недоступен. Он не возвращает потерянные конечности и погибших героев. При старте герои занимают соседние клетки вокруг костра в порядке отряда: сверху, слева, справа, снизу (до четырёх игроков). При переходе на другой участок весь отряд появляется вместе на одной клетке у входа. Герои могут стоять друг в друге; при совпадении глубины свой герой виден поверх союзников, а персонаж ниже по экрану перекрывает стоящего выше. В одиночной сессии герой появляется сверху от костра.

Мир и бой используют общие палитры и рисунки деревьев и земли. Узкие тропы соединяют выходы внутри каждой доступной области, с участками естественной земли, утоптанной дорожки и мелкой брусчатки. Соседние параллельные дорожки не сливаются в широкие площадки. Каменные пятна редки; крупные формации имеют низкий округлый силуэт. Дома имеют деревянные настилы и соединённые стены с непрерывной кладкой. Размер крыши зависит от размеров дома и закрывает задние стены. Вся крыша начинает становиться прозрачной, когда перекрывает голову героя в настоящем дверном проёме, и остаётся открытой, пока кто-либо из отряда внутри. Когда дом и вход пусты, крыша восстанавливается. Если герой снаружи сбоку или сзади, через закрывающую его часть крыши или стены проступает только его силуэт; остальной дом и содержимое остаются закрытыми. Наведение курсора и планирование пути не раскрывают крышу и стены дома. Кроны качаются; водоёмы и лужи имеют связные неровные берега с плавными изгибами, а рябь остаётся внутри контура воды. Рисунок берега сохраняет проходимость клеток и сухие перемычки. Мягкий свет вокруг каждого героя и костров постепенно уступает темноте вдали.

Сохраняется одна сессия в этом браузере. Одиночная игра записывает её при старте, переходе в другой чанк, победе, выходе из боя и выходе в главное меню. Выход во время боя сохраняет точные ход, броски и раны; продолжение восстанавливает очередь инициативы и ожидающее действие героя. Закрытие или обновление страницы в одиночной игре откатывает к последней контрольной точке. Смерть немедленно удаляет одиночное сохранение. Открытие лобби сохраняет прежнюю сессию; новый поход заменяет её после старта. Сетевой хост автоматически сохраняет поход в тот же слот, включая выход со страницы; гости этот слот не меняют. Старые сохранения прототипа удаляются без миграции.

На каждом участке патрулируют 2–4 группы анимированных врагов: обычные по 1–4 участника, эпические по 1–3 и редкие одиночные мини-боссы. Стаи держатся вместе и обходят препятствия. При сближении до 5 клеток вся группа начинает преследование; чуткие охотники замечают героя раньше, с 8 клеток. Для обнаружения нужна прямая видимость и доступная область. Стая преследует по всему текущему участку и переключается на ближайшего доступного героя, когда тот оказывается ближе прежней цели. Новое появление отряда защищено от немедленного столкновения.

В одиночной игре бой начинается при сближении героя с мобом до 1 клетки, если между ними нет непрозрачной преграды и область доступна. При старте целиком присоединяются все стаи, уже преследующие героя в текущем чанке, независимо от расстояния. Дополнительно один раз собираются соседние группы в радиусе 5 клеток от инициаторов; присоединившиеся не вызывают цепочку подкреплений. Во время одиночного боя мир замирает. По завершении удаляются только убитые враги; после побега живые остаются в мире. В кооперативе действуют описанные выше независимые бои и присоединение героев по длине пути; враги резервируются за конкретным боем, а после его завершения удаляются только убитые участники.

Процент победы над врагами не показывается: исход ручного боя зависит от решений игроков. Наведение мыши или короткий тап выделяет возможных участников встречи.

Победите четырёх сезонных боссов: весны, лета, осени и зимы. Смерть завершает одиночную сессию без автоматического лечения, возвращения к костру или загрузки погибшего героя. В кооперативе уцелевшие герои могут продолжить путь. Каждый герой выбирает одно действие в свой ход; режима автобоя и управления скоростью боя нет. Одиночные сохранения допускают одного героя, сетевые комнаты — до четырёх.

## Сезонные боссы

В каталоге 50 боссов: 13 весенних, 13 летних, 12 осенних и 12 зимних. Каждый получает собственное основное умение и два дополнительных. Для похода кубики по сиду выбирают по одному боссу каждого сезона.

Незаметный таймер сверху отсчитывает 20 минут на любой сложности. Затем босс появляется рядом со случайным живым героем, выбранным кубиком по сиду, и нападает на ближайших участников. В каждом сезоне есть один алтарь: подойдите к нему и подтвердите досрочный призыв. Полные 20 минут до следующего сезона начинаются только после победы над текущим боссом. Пока он жив, следующий призыв недоступен и отсчёт не идёт. Уже идущий бой не прерывается, босс остаётся в мире до победы над ним.

Отсчёт, живые боссы и победы сохраняются при выходе хоста и продолжении игры. Старый поход без таймера получает полный первый интервал. После победы над всеми четырьмя боссами и завершения остальных текущих боёв поход заканчивается победой. Правила и ограничения — [ADR 0025](docs/adr/0025-seasonal-bosses-and-altars.md).

## Сложность

| Профиль | HP врагов | Урон врагов | Эпическая группа | Мини-босс в чанке | Будущая редкая добыча |
|---|---|---|---|---|---|
| Легкая | ×1,28 | ×1,14 | 26% | 8% | ×1 |
| Нормальная | ×1,36 | ×1,23 | 36% | 12% | ×1,25 |
| Сложная | ×1,55 | ×1,29 | 46% | 18% | ×1,5 |

Сложность фиксируется при старте, сохраняется в сессии и применяется к параметрам врагов. Множитель урона действует на урон врага, включая броски и обычные периодические эффекты. Горение с фиксированным уроном по числу зарядов не масштабируется. Вероятность эпической группы проверяется у группы, не занятой мини-боссом. Коэффициент редкой добычи пока хранится только в данных.

## Проверка

```sh
npm run check
npm run simulate -- --runs 100
npm run audit:availability -- docs/reports/content-availability.json
npm run simulate:campaign -- --runs 100 --workers 8 --details compressed
```

`check` запускает проверку контента, TypeScript, тесты и production build. Симулятор перебирает составы от одного до четырёх из девяти героев и все встречи. По умолчанию на каждую комбинацию приходится 100 seeds; отчёт — `docs/reports/balance.json`. Первоначальная проверка девяти одиночных героев на трёх сложностях: [отчёт](docs/reports/solo-roster-balance.md). Результаты — исходная точка балансировки, а не доказательство готовности полного Run.

`simulate:campaign` проверяет полный поход с четырьмя боссами, накоплением добычи и постоянными ранениями. Время виртуальное, ожидания таймеров нет. `--runs 100` означает 100 походов на каждый размер отряда и сложность, всего 1200. Рядом с JSON создаётся наглядный HTML-отчёт; при `--details compressed` подробности каждого похода сохраняются в `.json.gz`. [Методика, команды и ограничения](tools/balance-simulator/README.md).

`npm run validate` также проверяет доступность каталогов через игровые пулы, источники аур и экипировку комплектов. `audit:availability` сохраняет список путей получения и отсутствующих записей. [Проверка доступности контента](docs/reports/content-availability.md): 500 обычных противников и 50 боссов, 4 861 предмет, 500 комплектов, 150 аур и 28 аур комплектов. Каталоги доступны между разными походами; один поход не обязан показывать их целиком.

Результаты настройки и независимой проверки: [баланс походов](docs/reports/balance-summary.md). [Состояние тестов и совместимость сохранений](docs/reports/balance-verification.md).

Проверка карты включает 10 000 сезонных профилей seed, 10 000 реальных участков с парными проходами и полные потоковые проверки больших миров. Полный перебор 10 000 больших графов вынесен в отдельный режим `WORLD_EXHAUSTIVE=1`. Подробности и границы проверки — в [отчёте карты](docs/reports/map-validation.md).

Проверка браузера (первый запуск скачивает Chromium):

```sh
npx playwright install chromium
npm run test:e2e
```

Playwright собирает production-версию и запускает отдельный сервер на порту 4173. Он проверяет взаимодействие с картой, переходы и бой внутри игрового экрана, сохранения, свет, границы камеры и компоновку узких и горизонтальных экранов без прокрутки документа. Детерминизм, победы и поражения дополнительно проверяются в game-core. Тесты используют отдельный профиль браузера. На CI Linux для установки зависимостей браузера используйте `npx playwright install --with-deps chromium`.

```sh
npm run build
npm run preview
```

Статическая production-сборка: `apps/client/dist`. Секреты и внешние сервисы для локального среза не требуются.

## Принятые правила

После первого акта выбор Heaven/Hell фиксируется до конца Run. Смена стороны и смешанный Purgatory исключены. Времена года существуют только в первом акте. Эти решения заменяют противоречащие им фрагменты исходной спецификации.

Скрытая сумка хранит собранные находки и все снятые вещи и изученные навыки. Отдельного окна сумки нет: её содержимое выбирается через соответствующий слот персонажа. Двуручное оружие возвращает обе заменяемые вещи, а при его снятии возвращается одним предметом. Несобранные награды теряются после предупреждения; содержимое сумки сохраняется. Реализованы личные награды боя и структур, монеты и замена предметов и двух найденных навыков в походе. [Добыча и скрытая сумка](docs/adr/0027-loot-pickup-and-slot-inventory.md).
