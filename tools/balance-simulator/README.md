# Ускоренные симуляции баланса

```sh
# 100 походов на каждый размер отряда и сложность: всего 1200.
npm run simulate:campaign -- --runs 100 --workers 8 --seed campaign-holdout-v1 --output docs/reports/campaign-balance.json

# Контроль с добычей и без замены стартовых вещей/навыков.
npm run simulate:campaign -- --runs 100 --workers 8 --modes progression,starter --output docs/reports/campaign-controls.json

# Старый инструмент: изолированные встречи из каталога encounters.
npm run simulate -- --runs 100
```

## Что измеряется

Победа — уничтожение всех четырёх сезонных боссов. Три сложности проверяются на одинаковых сидах и составах. Комбинации различных героев равномерно чередуются отдельно для 1, 2, 3 и 4 игроков. На малых выборках нельзя судить о конкретном составе.

Поход использует настоящие правила боя, генерацию групп, личные счётчики кубиков, ранения и утрату конечностей, добычу, сумку, замену вещей, навыки и бонусы комплектов. Бот оценивает ожидаемую пользу действий по известным характеристикам; будущие результаты кубиков ему недоступны. Сбор и экипировка не восстанавливают здоровье бесплатно. Костры работают только там, где они сгенерированы, и не возвращают утраченные части тела.

Это **модель заданного маршрута**, а не полноценный бот навигации: отряд держится вместе, посещает очередную точку не чаще чем раз в три игровые минуты, выбирает обычную группу, если она доступна, и осматривает до двух найденных сундуков за сезон. Столкновения на пути, объединение соседних групп, сетевые задержки и время размышления человека не моделируются. Неподвижный отряд прекращает перемещения. Без ранних призывов боссов поход занимает примерно 80 игровых минут плюс бой с последним боссом.

**Ни таймеры, ни анимации не ожидаются в реальном времени.** Между событиями игровые часы перескакивают к ближайшему событию. Длительность боевых анимаций добавляется только к виртуальному времени. Рабочие процессы считают независимые походы параллельно.

## Отчёт и ограничения

JSON содержит каждый исход, состав, бои, ранения, экипировку, число кубиков, время и допущения. Рядом записывается HTML с результатами. Ошибка симуляции прерывает серию и сохраняет незавершённый отчёт; она не считается поражением. Ничья по лимиту раундов и превышение лимита похода учитываются как `timeout`.

Проценты сопровождаются 95% интервалами Уилсона; парные сравнения используют совпадающие сиды. Время успешных походов считается отдельно от ранних поражений. Проверяются хеш контента и отпечаток исходников до/после серии. Для итоговой проверки исходники должны оставаться неизменными (`sourcesUnchanged: true`).

Калибровочные сиды начинаются с `balance-train`, проверочные — с `balance-holdout`. Параметры `--tuning` предназначены для экспериментов с JSON переопределений; окончательные числа должны находиться в игровых данных. Не подбирайте параметры по проверочной выборке и не выдавайте показатели бота за измеренный процент побед людей.

Ориентиры пользователя: лёгкая — около 30%, нормальная — около 15%, сложная — 5–10%, успешный поход — 60–90 минут. Даже попадание в эти интервалы на агрегате не доказывает одинаковую сложность каждого героя, состава или босса: проверяйте разбивку и слабые места отдельно.
