# Действующие правила боя

Ручной пошаговый бой на детерминированных кубиках. Герой выбирает одно
действие за собственный ход: атаку, навык с перезарядкой либо побег.
Два одноручных оружия выполняют последовательно два отдельных удара в
пределах одной атаки. Враги принимают решения в свой ход. Автобоя героев нет.

Актуальное решение: [ADR 0018](../adr/0018-unified-attributes-anatomy-and-turn-portraits.md).
Определения действий: [навыки](SKILL_CATALOG.md) и [ауры](AURA_CATALOG.md).

## Атрибуты

| Атрибут | Использование |
| --- | --- |
| Инициатива | `1d20 + Инициатива` задаёт место в очереди. |
| Сила | Масштабируемый урон, лечение и щиты используют `max(0, power + powerBonus)`. |
| Уклонение | Порог попадания по участнику. |
| Точность | Вычитается из Уклонения цели. |
| Стойкость | Прибавляется к порогу критического удара по участнику. |
| Критический удар | Вычитается из порога отдельной проверки крита. |
| Проворность | Порог побега: `15 + уровень сильнейшего живого врага − Проворность`. |
| Удача | Порог повышения редкости в `rollRewardRarity`: `20 − Удача`. |

Бонусы экипировки и активных аур входят в применимый атрибут. Сила
исцеления, магическая и физическая сила не являются отдельными атрибутами.
Броня — защита конкретной поражённой части; у участников без анатомии
используется общая `stats.armor`.

## Очередь и ход

В начале встречи все бросают `1d20 + Инициатива`; больший итог ходит
раньше. Равные участники бросают отдельные `1d20` без бонусов. Новое
равенство повторяет проверку только внутри соответствующей подгруппы.
Изменение атрибута после броска не переставляет уже определённую очередь.
Поздние участники бросают инициативу и входят в очередь на границе
следующего раунда; при равенстве с уже участвующим героем тот тоже
участвует в разрешении равенства.

Лента портретов постоянно показывает текущего участника слева и следующего
справа от него. Броски инициативы проигрываются на портретах одновременно,
добавление бонуса — после выпадения грани. Повторные броски имеют отдельные
этапы. Порядок открывается после анимации, по уже показанным событиям;
сетевая задержка не позволяет увидеть будущие результаты. Погибшие и
сбежавшие удаляются после соответствующего события. Уменьшение движения
убирает прокрутку и перелёты, сохраняя момент раскрытия результата.

В начале собственного хода проходят соответствующие тики аур. Герой
выбирает действие и допустимую цель; затем показываются броски и результат.
Конец хода вызывает свои тики и уменьшение применимых сроков. Кулдауны
отсчитываются собственными ходами. Успешный или неудачный побег расходует
одно действие и касается только бросавшего героя.

## Применение карты и отмена

Карта при drag немного поднимается и остаётся в веере. SVG-дуга соединяет
её верхнюю кромку с указателем или примагниченной целью. Область захвата
цели шире видимой рамки, а уже выбранная цель удерживается при небольшом
движении указателя. Для ручного адресата отпускание вне допустимой цели
отменяет действие.

Действия на себя, массовые, случайные и действия с единственной допустимой
целью применяются при отпускании внутри окна боя, кроме области отмены.
Подсказка — «Отпустите для применения». Случайную цель определяет только
симуляция: прицел не раскрывает её и не бросает дополнительные кубики.
Пассивный повтор после массового действия сохраняет прежнего первого
допустимого представителя; способ прицеливания эти правила не меняет.

Полупрозрачная область «Отмена» находится у верхнего края справа на
desktop и слева при ширине до 600 px либо указателе `coarse`. Лента
портретов временно освобождает ей место, не сдвигая бойцов. При наведении она подсвечивается,
дуга краснеет; отпускание отменяет выбор. `Esc`, уход фокуса, скрытие
страницы, изменение размеров и смена хода также отменяют незавершённый
жест. Отпускание за пределами окна боя не применяет карту.
Подробности интерфейса: [ADR 0019](../adr/0019-card-aiming-and-cancel-zone.md).

## Прямой удар

1. Для цели с анатомией отдельный `1d20` определяет часть тела:
   `1–11` торс, `12–13` левая рука, `14–15` правая рука, `16–17` левая
   нога, `18–19` правая нога, `20` голова. Отсутствующая часть заменяется
   торсом до определения защиты.
2. Другой `1d20` проверяет попадание. Натуральная `1` — промах,
   натуральная `20` — попадание. Иначе нужно
   `грань > Уклонение цели − Точность атакующего`.
3. После попадания отдельный `1d20` проверяет крит:
   `грань ≥ 20 − Критический удар + Стойкость цели`. Натуральная `20`
   всегда критическая. Гарантированный крит оставляет сам видимый бросок.
4. Рассчитываются кубики урона, явно заданная Сила с коэффициентом,
   плоский бонус и дополнительные кубики действующих эффектов.
   Крит удваивает всю полученную сумму до защиты. Повторного броска
   кубиков урона за крит нет.
5. Защитник бросает кубики локальной брони, затем применяются остальные
   подходящие уменьшения, полное блокирование, защита отряда и щиты.
   Оставшийся урон получает фактически поражённая часть.

Для брони `A = max(0, floor(эффективная броня))`: полные двадцатки дают
`floor(A / 20)d20`, ненулевой остаток `R = A % 20` — `1dR`.

| Броня | Броски защитника |
| --- | --- |
| 0 | Нет броска |
| 1 | `1d1` |
| 8 | `1d8` |
| 20 | `1d20` |
| 21 | `1d20 + 1d1` |
| 45 | `2d20 + 1d5` |

Сила не добавляется к кубикам защиты. Урон, обходящий броню, также обходит
плоское уменьшение после неё, но не отменяет поглощающие щиты и подходящие
особые правила защиты. Незащищённого отрицательного урона не возникает.

## Лечение, щиты и периодические эффекты

Прямое лечение навыком имеет отдельную проверку критического исцеления:
`1d20 ≥ 20 − Критический удар` без Стойкости получателя; натуральная `20`
всегда крит. Удваивается готовое лечение, включая явно заданную Силу.
Создание щита, периодические тики и реактивное лечение вроде передачи
исцеления не получают эту критическую проверку.

Наличие `scaling` означает добавление Силы источника, а не получателя.
Дробный коэффициент округляется вниз. Без масштабирования Сила к лечению
или щиту не добавляется. Периодический урон сохраняет свой плоский бонус
источника; `damageBonusDice` применяется к прямым ударам, не к тикам.

Ауры считают длительность в ходах носителя и срабатывают в указанную
фазу. Каждый независимый слой сохраняет собственный срок и источник.
Щиты имеют собственные слои ёмкости и сроков. Специальные проверки и
условия смотрите в [каталоге аур](AURA_CATALOG.md).

## Ранения и потеря частей

`current` части может быть отрицательным. Пока часть присутствует, обычное
лечение может вернуть её выше нуля.

- При `current ≤ 0` рука/нога не функционирует, но остаётся на модели.
- При `current ≤ −ceil(max / 2)` часть теряется: `lost = true`.
- Потеря головы или торса означает смерть. Их нулевые/отрицательные
  значения выше порога потери сами по себе не мешают действовать.
- Для действия нужна хотя бы одна работоспособная рука. Повреждение ног
  влияет на движение. Потерянные части обычное лечение/отдых не возвращают.

Полоска суммарного боевого здоровья не подменяет эти правила. Живой герой
с тяжёлыми ранами сохраняет положительный служебный `hp`, пока голова и
торс присутствуют.

## Удача и граница выдачи наград

Доступен чистый API `rollRewardRarity(base, luck, rng)`:
`common → rare → epic → legendary`. Успех `1d20 ≥ 20 − Удача` поднимает
редкость на одну ступень и даёт следующий бросок. Первая неудача или
легендарная редкость завершает цепочку. Особых правил натуральной `1/20`
для этой проверки нет. Уже легендарная награда не требует броска.

API принимает личный RNG получателя и возвращает его обновлённую копию
вместе с итоговой редкостью и журналом проверок. Его ещё нужно подключить
к системной выдаче наград; действующий интерфейс наград не объявляется
готовым только из-за наличия этого расчёта.
