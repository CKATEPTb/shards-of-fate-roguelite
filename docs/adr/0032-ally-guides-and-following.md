# 0032 — Ally edge guides and continuous following

## Decision

Co-op allies outside the visible map have named head portraits at the screen edge. Portraits show the hero's equipped appearance and an arrow toward their location. Guides also work across chunks and use a visible portal or staircase when it directly connects to the ally. Portrait hit areas avoid other portraits and exit arrows. The selected ally has a gold outline and a small following label; this guide remains available when they are onscreen.

Clicking a portrait selects that hero as a persistent travel target. Selecting a different portrait changes the target. The follower uses ordinary pathfinding to approach an unoccupied cell within two walkable steps of the leader's short route lookahead. It continues when the leader moves, rather than stopping permanently after reaching their old position. Nearby stationary heroes wait instead of stacking on the leader.

Manual movement, including a clicked exit, cancels following immediately. Explicit object and rescue commands also take ownership of movement and cancel following. Opening equipment or collecting loot does not cancel it. Combat, disconnection and inability to move suspend the controller; it resumes when the controlled hero can travel again. Following a fallen ally approaches their body but never revives them automatically. The mode is local to the current play session.

## Routing

`planCoopFollow` returns an ordinary move, a transport interaction, or a wait. A moving leader supplies up to four tiles of lookahead so followers do not race toward a distant endpoint. Local routes use the existing weighted A* and gate rules.

Cross-chunk routes search deterministic transit metadata. Detached pockets are separate graph regions, paired gates connect their correct peers, and portals are explicit transport edges. Basement routes use the corresponding stairs down and up. Every immediate travel leg is checked against actual local terrain before issuing movement. Remote terrain is not generated by the search; immutable chunk plans and remaining routes are cached, with eight destination maps retained per world.

## Networking and lifecycle

Follow intent is a client controller; it adds no wire commands, actor snapshot fields or server state. Only normal `move` and `interact` commands enter the existing prediction/host flow. Unchanged route endpoints are retained, evaluations are throttled, and retries are delayed. Commands include the predicted movement origin and preserve fractional movement only when the new route starts with the same tile.

Guests do not wait for the host between movement legs. Portal/stair interactions wait until both predicted and confirmed actors are stopped on the same transport tile with the same chunk and transition count. The command guard is recorded before sending because prediction can synchronously publish a new state. A rejected prediction that returns to an unchanged idle state gets a delayed recheck instead of stalling forever.

Existing combat entry, dice, reward and resurrection rules remain authoritative. This feature requires no additional protocol version or server change.
