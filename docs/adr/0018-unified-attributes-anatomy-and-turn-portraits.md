# 0018 · Единые атрибуты, ранения и портретная очередь

## Решение

Боевые атрибуты, проверки попадания, критов и защиты разделены. Прежние
раздельные характеристики силы урона и исцеления заменены единой Силой.
Это решение уточняет действующие правила из ADR 0012–0017; исторические
записи сохраняются. Текущий справочник — [COMBAT](../reference/COMBAT.md).

## Восемь атрибутов

| Атрибут | Поле | Назначение |
| --- | --- | --- |
| Инициатива | `initiative` | Прибавляется к первоначальному `1d20` очереди. |
| Сила | `power` | Прибавляется к урону, лечению и ёмкости щита, если действие явно имеет масштабирование. |
| Уклонение | `evasion` | Задаёт порог попадания по носителю. |
| Точность | `accuracy` | Снижает порог попадания по цели. |
| Стойкость | `resilience` | Повышает порог критического попадания по носителю. |
| Критический удар | `crit` | Снижает порог отдельной проверки критического урона или прямого лечения. |
| Проворность | `agility` | Снижает порог собственного побега. |
| Удача | `luck` | Снижает порог повышения редкости награды в API расчёта наград. |

Ауры используют соответствующие `*Bonus`, в том числе `powerBonus`,
`resilienceBonus`, `luckBonus`. Для масштабируемого действия применяется
`max(0, power + powerBonus)` с его коэффициентом и округлением вниз.
Плоский `damageBonus` и `damageBonusDice` остаются отдельными эффектами.
`healing`, `healingBonus` и `scaling: healing` могут читаться адаптерами
старых данных; отдельной характеристики лечения в текущей игре нет.
Старое значение `scaling: healing` при исполнении означает ту же Силу.

Броня находится на поражённой части тела. `stats.armor` нужен для
участников без анатомии; броня не включается девятым общим атрибутом.

## Независимые броски

Попадание: натуральная `1` на `1d20` всегда промах, натуральная `20`
всегда попадание. Для остальных граней требуется
`d20 > Уклонение цели − Точность атакующего`.

После попадания бросается другой `1d20` на крит:
`d20 ≥ 20 − Критический удар атакующего + Стойкость цели`.
Натуральная `20` всегда критическая. Прямое исцеление имеет отдельную
критическую проверку без Стойкости получателя. Крит умножает на два весь
готовый результат, включая Силу и применимые бонусы. Дополнительного
повторного броска кубиков урона за крит нет. Периодические тики аур и
создание щита не получают такую проверку. Гарантированный крит не отменяет
проверку попадания и видимый критический бросок.

Защита: эффективная локальная броня `A` округляется вниз и ограничивается
нулём. Защитник бросает `floor(A / 20)d20` и, если остаток `R = A % 20`
ненулевой, ещё `1dR`. Примеры: `20 → 1d20`, `21 → 1d20 + 1d1`,
`45 → 2d20 + 1d5`. При нулевой броне бросков нет. Сила к ним не добавляется;
результаты вычитаются из урона. Затем действуют остальные правила защиты
и щитов. Локальная броня берётся с фактически поражённой части.

Проверки используют личный детерминированный поток бросающего: защита —
поток защитника, попадание и крит — поток атакующего. Интерфейс только
проигрывает события и не расходует RNG. Подпись обычного проверочного
кубика — «Сила не добавляется»: это не отрицает изменение порога его
собственными атрибутами.

## Два порога повреждения части

Для части с максимумом `max` действуют два порога:

- `current ≤ 0`: рука или нога перестаёт функционировать, но ещё
  присутствует, видна на модели и поддаётся обычному лечению;
- `current ≤ −ceil(max / 2)`: часть потеряна, `lost = true`.

Голова и торс при нуле и отрицательных значениях выше порога потери не
убивают героя. Смерть наступает при потере головы или торса. Возможность
действовать дополнительно требует хотя бы одну работоспособную руку.
Потерянные части обычное лечение и отдых не восстанавливают. Попадание в
уже отсутствующую конечность перенаправляется в торс до расчёта его брони.

Например, при `max = 100` рука отключается на `0`, теряется на `−50`, а
при `max = 101` порог потери равен `−51`. `lost` сохраняется явно, чтобы
отличать отключённую часть от отсутствующей.

## Постоянная очередь портретов

Сверху арены находится лента голов и плеч героев и врагов. Начальные
броски инициативы показываются одновременно на соответствующих портретах:
сначала вращение `1d20`, затем грань и добавление бонуса. Равенства
разрешаются отдельными этапами чистого `1d20`. Карточки сортируются после
показа всех нужных результатов; окончательный порядок из сетевого
снимка не раскрывается заранее.

Первый портрет — текущий участник, второй — следующий. После хода лента
сдвигается; погибшие и сбежавшие уходят после воспроизведения события.
Позднее подкрепление видно до его включения в очередь следующего раунда.
Инициатива не дублируется в прежних плашках бросков со стрелками. Остальные
броски продолжают показываться у соответствующих участников.

## Граница системы Удачи

`rollRewardRarity(base, luck, rng)` рассчитывает лестницу
`common → rare → epic → legendary`. Каждый успех `1d20 ≥ 20 − Удача`
поднимает редкость на одну ступень и запускает новую проверку. Первая
неудача или легендарная редкость заканчивает цепочку. Здесь нет особого
исключения для натуральной `1` или `20`.

API принимает личный RNG получателя, не изменяет переданный объект и
возвращает редкость, записи бросков и обновлённый RNG. Системный интерфейс
выдачи таких наград ещё не подключён; наличие API не означает, что
обычные награды похода уже используют Удачу.
